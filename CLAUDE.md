- The user's original scripts live outside this repo in `C:\Claude\--LASER ENGRAVING TOOLS--\` (private). Read-only: don't edit, add, or delete inside without asking, and never copy them into this repo.
- `engrave_core.py` style "photo" is a port of `C:\Claude\--LASER ENGRAVING TOOLS--\Imag-R Mimic Processing\image_processing.py`. With the same settings and `remove_bg` off, its output must stay **pixel-identical** to the original. If you change the pipeline on purpose, say so and say why. If you refactor, re-run a comparison against the original script (via `render()`) for all four dither modes.
- Intentional differences from the original: settings are passed in, invert/mirror are separate flags (acrylic turns both on), EXIF rotation is applied on load, and Stucki uses numba (falls back to plain Python if numba is missing).
- Style "comic" (`comic()`): bilateral flattening -> tone bands filled with patterns (`PATTERN_SETS`) + adaptive-threshold ink lines. With invert, bands flip but ink stays burned.
- `render()` is the single entry point for both styles; `save_outputs()` writes the PNG plus optional preview JPG and outline SVG. `test_card()` reuses `render()`.
- Background models: `core.BG_MODELS` (rembg names → label, size, speed). Every cache is keyed by model (disk tags `ai-<model>`, `fix-<model>-…`; app caches keyed `(path, model)`). Models download via pooch to `%USERPROFILE%\.u2net`; `sys.stderr/stdout` are redirected to devnull when None so pooch's progress bar can't crash the windowed exe.
- Stroke kinds: `keep`/`remove` = smart (GrabCut); `paint_keep`/`paint_remove` = plain anti-aliased brush (`_paint_stroke`), exact pixels only. Brush strokes are firm labels for later smart strokes (`KEEP_KINDS`).
- Cut-out fixes: strokes `(kind, radius, [(x, y), ...])` in source-image pixels, stored per file in `fixes.json` (`DATA_DIR`, keyed by path + mtime). `core.refine_alpha()` applies strokes **sequentially** (`_apply_stroke`, one GrabCut per stroke on top of the previous result) and is **direction-locked**: a Keep stroke may only add (alpha only rises), a Remove only subtracts, and only in changed regions touching that stroke. This is a firm user requirement; keep it. The new stroke's label is pre-spread over nearby same-color pixels (`_similar_region`: fixed ΔE 12, short reach; a wider tolerance leaked in testing). GrabCut at ≤400 px with a **seeded RNG** (preview == saved file). Edges near the change are re-softened with a guided filter, using max/min so softening also respects direction. Prefix results are cached in memory (app `step_cache`) and final results on disk.
- Disk cache `cutout_cache/` under `DATA_DIR`: AI masks and fixed masks keyed by path + mtime + size + `CACHE_VERSION` (+ `stroke_key`). **Bump `CACHE_VERSION` whenever cut-out output changes**, or stale masks will be served. The app warms up the model and prefetches AI cut-outs for listed files in a background thread.
- The user wants to test changes from source (`Laser Engraver.bat`) before a new installer is built. Don't run build.bat unless asked. The app caches the AI cut-out and the refined alpha separately, so slider changes don't re-run either.
- Background removal uses rembg (u2net model in `%USERPROFILE%\.u2net`), imported lazily.
- Test with the window off-screen (geometry like `1400x900-6000+0`) or headless. Don't pop windows over the user's screen or screen-grab their desktop.
- Design mode: `design.py` (engine) + `design_ui.py` (`DesignController`, attached to `App` as `app.dc`). A design is a plain JSON-able dict; layers bottom→top, positions are centers in inches, rotation clockwise degrees. Each layer renders to `ink`/`cover` masks (cached by content, not position, so moves are instant); photos are rotated *before* dithering. Mirror is applied to the whole design only at export. Material/DPI/invert/mirror/outline are design-wide (`design.GLOBAL_FIELDS`); photo layers keep their own `settings` (`LAYER_SETTING_FIELDS`) and `strokes`. When a photo layer is selected, App's controls show its settings and `App.on_change` → `dc.sync_from_vars()` writes edits back; fix strokes go to the layer via `App.strokes_for/_strokes_mut`. Projects: `.lep` = zip of `project.json` + `assets/` (content-hashed copies), unpacked to `DATA_DIR/project_assets`; layers keep the original file name in `name` for the list. The unsaved design persists in settings.json (`design_state`).
- Two design views: "Layout" (`Renderer(draft=True)`, `DRAFT_DPI`, photos as plain grayscale, default) and "Design" (full engraving). Only the shown view renders; the other is marked stale (`dc.stale`). View pixels ≠ design pixels in Layout: use `dc._screen()` for design-px math and the shown view's renderer (`_view_renderer`) for hit-testing in view px. Snapping: `dc._snap` / `_snap_targets` (AABB edges/centers of other layers + canvas; Alt disables), also during resize (`dc._scale`, unrotated items only). Resize anchors on the opposite corner by default (`scale_from`, Ctrl flips it). Ctrl+click cycles through stacked items.
- Engrave / score / cut: every layer has `op` ("engrave" | "score" | "cut"; shapes default cut). Layers saved before v1.11 have a `cut` bool instead: `_with_defaults` converts it (and keeps old SVG layers' output via `jobs_from` + `box="page"`, text weld off). Score/cut lines come from `vectors.layer_vectors` → `{"cut"|"score": polylines}` (cached relative to position in `Renderer.layer_vectors`, kept in `Renderer.vecs`); fontTools letter outlines (adaptive flattening, `TOL_IN`), contour tracing for logos/photos. Per-layer `weld` / `outer` / `offset_mm` run through `vectors.shape_ops` (shapely; one group per letter / drawing item with its fill rule). `design.save_engraving` writes the PNG, one file per job `_cut` / `_score` (.svg/.dxf by `cut_format`; mm, red #FF0000 / blue #0000FF hairlines, optional **green** #00FF00 canvas frame, R12 DXF layers CUT/SCORE/FRAME) and `combined` ("none"/"svg"/"pdf"/"svg+pdf"; old projects store a bool) `_combined.svg` / `.pdf` (`vectors.write_pdf`, PyMuPDF). Blue is reserved for score, so the frame must not be blue. Target software: Trotec Ruby, xTool XCS, LaserGRBL (user's), LightBurn; none of the imports have been tested in those programs (README table is from their docs). Test copy: `design.scaled_design(design, factor)` scales every length field (`_SCALED_DESIGN`/`_SCALED_LAYER`; add new inch/mm/pt fields there) but keeps DPI and settings; `dc.export(factor=…)` saves it with a `_test` suffix through its own Renderer.
- Vector files (layer type "svg", label "Vector"; SVG / PDF / AI / DXF): `vecfile.load(path)` → doc at real size with items (stroke/fill hex, width, cap/join, fill rule, Bézier subpaths in page inches), cached by path + mtime. SVG goes through `_prepare_svg` first because MuPDF ignores CSS `<style>` classes and `display:none`, treats px as 72 DPI, and draws text with built-in fonts: it inlines CSS (simple selectors), removes hidden elements, writes the real size into the root (96 px/in; 72 for files containing "Adobe Illustrator"), and replaces `<text>` with outline paths from the installed fonts (`_text_to_path`: tspans, text-anchor chunks, letter-spacing; checked against Edge's rendering). Desktop only (`_prepare_svg(mupdf=True)` → `_fix_for_mupdf`): MuPDF also ignores `fill-rule` / `fill-opacity` / `stroke-opacity` / `opacity` inside `style=""` (attributes work), drops every stroke-width unit, and ignores `currentColor`, `visibility`, nested `<svg>` x/y and `<use>` width/height on symbols, and draws rounded rects with a short kappa; the fix moves those style properties to attributes, converts widths to px, resolves currentColor/visibility, wraps nested svgs in a translate, replaces sized symbol uses with nested-svg copies and rounded rects with paths. Verified (user-approved): 20 of 23 Inkscape examples unchanged dot for dot; changed files now match `_load_svg_plain` item for item. Not fixed on purpose: gradients (MuPDF black, plain reader first stop), text on a path (desktop stand-in font, web drops it). Symbol sizes (both readers, `_symbol_size`): use width/height, else the symbol's, else 100% of the nearest viewport (SVG 2; checked against `inkscape --query-all`). PDF text / leftover SVG text → `get_svg_image(text_as_path=True)` re-read. DXF via ezdxf (`recover.readfile`, own INSERT/DIMENSION expansion so polylines stay closed, ACI 7 → black, $INSUNITS, y flipped). Every line color / fill color is a group (`s:#hex` / `f:#hex`) with a job (`JOBS`: engrave / score / cut / blank / ignore); `layer["jobs"]` stores choices, missing ones come from `vecfile.default_job` (`design.vector_jobs`). `render_svg` rasterizes engrave/blank items in drawing order (fills with their fill rule; lines ≥ 3 px via shapely buffers with the file's caps/joins). Layer fields: `parts` (item indexes; Break apart / Split by color), `box` ("content" bounds or legacy "page"), `line_mm`. Size math: `design.vector_box` / `vector_size`.
- Photos mode crop/rotate/size-by-height: Settings `rotate`, `crop_*` (fractions; shown as % in the UI via `CROP_FIELDS`), `size_by`/`height_in`; applied by `core.prepare()` after `load_source` (no-op at defaults, so the pixel-identical rule still holds). Fix strokes stay in un-cropped source coordinates. Design layers ignore these (their own crop/rotation).
- Job estimate: `core.raster_stats` (per-row first→last burn span) + `estimate_seconds`; App shows it (`set_estimate`); speeds saved in settings.json.
- Shortcuts: one dispatcher (`App._on_key` → `_run_action`) driven by a user-editable keymap (`shortcuts.py`: `ACTIONS`, `from_event`, `ShortcutsWindow`; non-default keys saved in settings.json `shortcuts`). Add new shortcuts as actions there, not with extra `bind_all` calls. Ignored while typing (except Ctrl combos) and inside dialogs; Esc is a fixed extra key for Pan. Compare split in `redraw` via `_with_original`.
- Scaling: per-monitor DPI aware (`ui_kit.set_dpi_awareness` in `main`). `ui_kit.Scaler` (`app.scaler`, `ui_kit.S`) sets factor = monitor DPI/96 × user UI size, resizes named fonts (`ui_kit.FONTS`; use "AppSection"/"AppTitle"/"AppSmall"/"AppBold", never literal font tuples) and the clam-based theme (`style_theme`), and scales every widget's pad/padding/wraplength/length from **base pixels at 100%**. After building or re-packing widgets, call `app.scaler.refresh(widget)` so their spacing gets scaled. Canvas sizes use `ui_kit.px()` (imported as `ui_px` in design_ui to avoid clashing with local `px` variables). Don't use image-based themes (sv-ttk): their images can't scale.
- Themes: palettes in `ui_kit.PALETTES` (light/dark); the active one is `ui_kit.P` — use `P["..."]` for any color, never hard-coded UI colors (canvas overlay accents excepted). `ui_kit.set_theme()` restyles ttk, recolors plain Tk widgets (`recolor`: Listbox/Text/Menu/Canvas/Toplevel) and sets the Windows title bar (`dark_title_bar`). New dialog windows: call `ui_kit.adopt(win)` (scale + theme). After any font-size change, ttk entries/comboboxes/spinboxes must be re-laid out (`Scaler._relayout_text`) or their text gets clipped (Tk caches the text position).

Styling the native clam tabs as a strip didn't work (the selected tab draws offset).
