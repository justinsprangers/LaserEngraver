# CLAUDE.md: LaserEngraver

Desktop app (tkinter) for preparing photos for laser engraving. See README.md for usage.

- **This is its own public git repo** (MIT; author set locally to the GitHub no-reply address). The parent `C:\Claude` repo ignores this folder. Never commit personal photos, projects, settings, or anything from outside this folder. Don't push unless the user asks.
- The user's original scripts live outside this repo in `C:\Claude\--LASER ENGRAVING TOOLS--\` (private). Read-only: don't edit, add, or delete inside without asking, and never copy them into this repo.
- `engrave_core.py` style "photo" is a port of `C:\Claude\--LASER ENGRAVING TOOLS--\Imag-R Mimic Processing\image_processing.py`. With the same settings and `remove_bg` off, its output must stay **pixel-identical** to the original. If you change the pipeline on purpose, say so and say why. If you refactor, re-run a comparison against the original script (via `render()`) for all four dither modes.
- Intentional differences from the original: settings are passed in, invert/mirror are separate flags (acrylic turns both on), EXIF rotation is applied on load, and Stucki uses numba (falls back to plain Python if numba is missing).
- Style "comic" (`comic()`): bilateral flattening -> tone bands filled with patterns (`PATTERN_SETS`) + adaptive-threshold ink lines. With invert, bands flip but ink stays burned.
- `render()` is the single entry point for both styles; `save_outputs()` writes the PNG plus optional preview JPG and outline SVG. `test_card()` reuses `render()`.
- Background models: `core.BG_MODELS` (rembg names → label, size, speed). Every cache is keyed by model (disk tags `ai-<model>`, `fix-<model>-…`; app caches keyed `(path, model)`). Models download via pooch to `%USERPROFILE%\.u2net`; `sys.stderr/stdout` are redirected to devnull when None so pooch's progress bar can't crash the windowed exe.
- Stroke kinds: `keep`/`remove` = smart (GrabCut); `paint_keep`/`paint_remove` = plain anti-aliased brush (`_paint_stroke`), exact pixels only. Brush strokes are firm labels for later smart strokes (`KEEP_KINDS`).
- Cut-out fixes: strokes `(kind, radius, [(x, y), ...])` in source-image pixels, stored per file in `fixes.json` (`DATA_DIR`, keyed by path + mtime). `core.refine_alpha()` applies strokes **sequentially** (`_apply_stroke`, one GrabCut per stroke on top of the previous result) and is **direction-locked**: a Keep stroke may only add (alpha only rises), a Remove only subtracts, and only in changed regions touching that stroke. This is a firm user requirement; keep it. The new stroke's label is pre-spread over nearby same-color pixels (`_similar_region`: fixed ΔE 12, short reach; a wider tolerance leaked in testing). GrabCut at ≤400 px with a **seeded RNG** (preview == saved file). Edges near the change are re-softened with a guided filter, using max/min so softening also respects direction. Prefix results are cached in memory (app `step_cache`) and final results on disk.
- Disk cache `cutout_cache/` under `DATA_DIR`: AI masks and fixed masks keyed by path + mtime + size + `CACHE_VERSION` (+ `stroke_key`). **Bump `CACHE_VERSION` whenever cut-out output changes**, or stale masks will be served. The app warms up the model and prefetches AI cut-outs for listed files in a background thread.
- The user wants to test changes from source (`Laser Engraver.bat`) before a new installer is built. Don't run build.bat unless asked. The app caches the AI cut-out and the refined alpha separately, so slider changes don't re-run either.
- Background removal uses rembg (u2net model in `%USERPROFILE%\.u2net`), imported lazily.
- Test with the window off-screen (geometry like `1400x900-6000+0`) or headless. Don't pop windows over the user's screen or screen-grab their desktop.
- Design mode: `design.py` (engine) + `design_ui.py` (`DesignController`, attached to `App` as `app.dc`). A design is a plain JSON-able dict; layers bottom→top, positions are centers in inches, rotation clockwise degrees. Each layer renders to `ink`/`cover` masks (cached by content, not position, so moves are instant); photos are rotated *before* dithering. Mirror is applied to the whole design only at export. Material/DPI/invert/mirror/outline are design-wide (`design.GLOBAL_FIELDS`); photo layers keep their own `settings` (`LAYER_SETTING_FIELDS`) and `strokes`. When a photo layer is selected, App's controls show its settings and `App.on_change` → `dc.sync_from_vars()` writes edits back; fix strokes go to the layer via `App.strokes_for/_strokes_mut`. Projects: `.lep` = zip of `project.json` + `assets/` (content-hashed copies), unpacked to `DATA_DIR/project_assets`. The unsaved design persists in settings.json (`design_state`). SVGs render with PyMuPDF.
- Two design views: "Layout" (`Renderer(draft=True)`, `DRAFT_DPI`, photos as plain grayscale, default) and "Design" (full engraving). Only the shown view renders; the other is marked stale (`dc.stale`). View pixels ≠ design pixels in Layout: use `dc._screen()` for design-px math and the shown view's renderer (`_view_renderer`) for hit-testing in view px. Snapping: `dc._snap` / `_snap_targets` (AABB edges/centers of other layers + canvas; Alt disables), also during resize (`dc._scale`, unrotated items only). Resize anchors on the opposite corner by default (`scale_from`, Ctrl flips it). Ctrl+click cycles through stacked items.
- Cut vs engrave: every layer has `cut` (shapes default True; layers loaded without the key stay False). Cut layers are skipped in the raster and turned into polylines by `vectors.layer_paths` (cached relative to position in `Renderer.cut_paths`); fontTools for letter outlines, PyMuPDF `get_drawings` for SVG paths, contour tracing for logos/photos. `design.save_engraving` writes the PNG plus `_cut.svg`/`_cut.dxf` (mm, red #FF0000, optional blue canvas frame, R12 DXF) and optionally `_combined.svg`. Target software: Trotec Ruby, xTool XCS, LaserGRBL (user's), LightBurn; alignment relies on the frame because import behavior varies. Test copy: `design.scaled_design(design, factor)` scales every length field (`_SCALED_DESIGN`/`_SCALED_LAYER`; add new inch/mm/pt fields there) but keeps DPI and settings; `dc.export(factor=…)` saves it with a `_test` suffix through its own Renderer.
- Photos mode crop/rotate/size-by-height: Settings `rotate`, `crop_*` (fractions; shown as % in the UI via `CROP_FIELDS`), `size_by`/`height_in`; applied by `core.prepare()` after `load_source` (no-op at defaults, so the pixel-identical rule still holds). Fix strokes stay in un-cropped source coordinates. Design layers ignore these (their own crop/rotation).
- Job estimate: `core.raster_stats` (per-row first→last burn span) + `estimate_seconds`; App shows it (`set_estimate`); speeds saved in settings.json.
- Shortcuts: one dispatcher (`App._on_key` → `_run_action`) driven by a user-editable keymap (`shortcuts.py`: `ACTIONS`, `from_event`, `ShortcutsWindow`; non-default keys saved in settings.json `shortcuts`). Add new shortcuts as actions there, not with extra `bind_all` calls. Ignored while typing (except Ctrl combos) and inside dialogs; Esc is a fixed extra key for Pan. Compare split in `redraw` via `_with_original`.
- Scaling: per-monitor DPI aware (`ui_kit.set_dpi_awareness` in `main`). `ui_kit.Scaler` (`app.scaler`, `ui_kit.S`) sets factor = monitor DPI/96 × user UI size, resizes named fonts (`ui_kit.FONTS`; use "AppSection"/"AppTitle"/"AppSmall"/"AppBold", never literal font tuples) and the clam-based theme (`style_theme`), and scales every widget's pad/padding/wraplength/length from **base pixels at 100%**. After building or re-packing widgets, call `app.scaler.refresh(widget)` so their spacing gets scaled. Canvas sizes use `ui_kit.px()` (imported as `ui_px` in design_ui to avoid clashing with local `px` variables). Don't use image-based themes (sv-ttk): their images can't scale.
- Themes: palettes in `ui_kit.PALETTES` (light/dark); the active one is `ui_kit.P` — use `P["..."]` for any color, never hard-coded UI colors (canvas overlay accents excepted). `ui_kit.set_theme()` restyles ttk, recolors plain Tk widgets (`recolor`: Listbox/Text/Menu/Canvas/Toplevel) and sets the Windows title bar (`dark_title_bar`). New dialog windows: call `ui_kit.adopt(win)` (scale + theme). After any font-size change, ttk entries/comboboxes/spinboxes must be re-laid out (`Scaler._relayout_text`) or their text gets clipped (Tk caches the text position).
- UI: `ui_kit.segmented()` + `seg_button()` for joined button groups (Mode, views, fix tools; style "Seg.Toolbutton", colored fix-tool variants), matching the web version's look. The settings notebook is a `ui_kit.StripNotebook`: native tabs hidden (`Strip.TNotebook.Tab` layout is empty) and `nb.strip` (a segmented strip packed above it) is the tab row; it rebuilds itself on add/insert/forget/hide and tab changes, so keep using normal Notebook calls. Styling the native clam tabs as a strip didn't work (the selected tab draws offset).
- Screenshots of the app without showing anything to the user: off-screen windows render blank, so make the window invisible and click-through instead (`root.attributes("-alpha", 0.01)` plus WS_EX_TRANSPARENT | WS_EX_LAYERED | WS_EX_TOOLWINDOW on the frame) and capture it with `PrintWindow(hwnd, dc, 2)`. Never grab the desktop. `section()` group boxes, and `ScrollTab` pages so notebook tabs stay pinned while content scrolls (build into `.inner`; use the outer object for notebook add/hide/select). In Design mode the photo views are disabled unless a photo layer is selected (`App.update_view_buttons`).
- When generating key/mouse events in tests, `<B1-Motion>` needs `state` with 0x100 (button held).
- App code layout: `App` in `engrave_app.py` mixes in `PanelsMixin` (app_panels.py), `PreviewMixin` (app_preview.py), `FixToolsMixin` (app_fixtools.py), `KeysMixin` (app_keys.py); shared constants in `app_common.py`; `selftest.py` for the build check. Put new methods in the mixin that matches their job. `STATE_FILE`/`FIXES_FILE` and the code that reads them stay in engrave_app.py (tests patch them there). Keep the project pyflakes-clean (`python -m pyflakes`).
- State: `App.save_state()` writes settings.json atomically, on close and every 60 s (`AUTOSAVE_MS`), skipping unchanged writes; the unsaved design restores from it.
- `engrave_app.py` and its mixins only handle UI. Keep processing logic in `engrave_core.py` so the CLI and app stay in sync.
- Material profiles live in `materials.json`. Keys starting with `_` are comments. Materials = contrast/brightness/gamma/invert/mirror; style presets (`presets.json`, `core.PRESET_FIELDS`) = photo or comic look settings. Keep the two separate. A built-in "Default" preset per style is generated from `Settings()` defaults, never stored. If you add a new photo or comic setting, add it to `PRESET_FIELDS`.
- `settings.json` and `output/` are git-ignored.
- Packaged with PyInstaller (one-folder) + Inno Setup via `build.bat` → `packaging/build.py`. Outputs `dist/`, `build/`, `installer/` are git-ignored.
- When frozen, `core.FROZEN` is true: user data goes to `%APPDATA%\LaserEngraver`, output defaults to `Documents\Laser Engraver`, bundled read-only files are under `core.HERE` (`sys._MEIPASS`). From source, everything stays in this folder. Keep new file paths going through `core.DATA_DIR` / `core.HERE`.
- `LaserEngraver.exe --selftest <report.txt>` runs photo, comic, and rembg headlessly; build.py runs it and refuses to make an installer if it fails. If you add a library, check it still passes.
- Bump `VERSION` in `engrave_core.py` for each release; the installer reads it. Keep the `AppId` GUID in `installer.iss` unchanged so upgrades replace the old install.
- Run with plain `python` (not `python -I`): packages are in user site-packages.

## Web version (`web/`)
- Static site, no build step: `web/worker.js` runs Pyodide 0.27.7 (NumPy, OpenCV 4.10, Pillow 10.2) and loads the repo's own `../engrave_core.py` and `../materials.json` via `web/engine.py`. Keep `engrave_core.py` importable without tkinter, numba or rembg (all are optional/lazy there) or the web version breaks. Test locally with the `laserengraver-web` launch config (http.server on port 8800 serving this folder; open `/web/`).
- `engine.py` swaps Stucki for the JS loop `stuckiJS` in worker.js (same float64 math) and copies rembg's U2netSession pre/post-processing around onnxruntime-web 1.20.1. If you change `_stucki_loop`, change `stuckiJS` too.
- Verified: photo style pixel-identical to desktop (all dithers, crop/rotate); u2net mask within 1/255; comic differs ~0.01% of pixels above 1200 px (cv2.resize/bilateral in the WASM build). Re-check with a desktop-vs-browser hash comparison after pipeline changes.
- Model: `web/models/u2net.onnx.part*` + `u2net.json` (sha256), made by `web/tools/split_model.py`; parts < 50 MB for GitHub. The worker caches them in Cache Storage (`laser-engraver-models-v1`); bump that name if the model files change. rembg's GitHub release can't be fetched from a browser (no CORS).
- UI is separate from the desktop's (no shared UI code): `index.html`, `app.js` (settings panels, presets/materials in localStorage, canvas preview), `style.css` (same palette as `ui_kit.PALETTES`, light/dark). Crop/rotate and fix strokes are per photo (in memory only); everything else is global, like the desktop. No Design mode yet.
- Fix strokes (phase 2): same tools, colors, keys and stroke format as the desktop; `engine._refined` runs `core.refine_alpha` with a per-file prefix cache; `render` also returns the Cut-out view (`_cutout_view`, copy of the desktop's). Brush size is screen px; radius in source px = size/2/zoom*factor, like `on_release` in app_preview.py.
- Materials in the web version: built-ins from `materials.json` are read-only (no rename/delete/overwrite; user requirement); personal ones live in localStorage `le.myMaterials` and can't reuse a built-in name.
- Hosting: GitHub Pages from the repo root; root `index.html` redirects to `web/`.
- Guided tour: `web/tour.js` (`STEPS`: target selector or function, optional `tab` to switch to, title, HTML text). Targets: ids, or settings sections by `data-sec` (slug of the section title, set in `section()`), so renaming a section title breaks its step. If you move or add a tool, update the matching step. Dimming uses a clip-path hole (large box-shadows didn't render reliably). Offered once per browser (`le.tourSeen`), after app.js fires `le-ready`. Sample photo: `web/samples/astronaut.jpg` (NASA, public domain).
